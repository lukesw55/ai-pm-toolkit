## 2026-09-16: B43: the README rewritten for the person deciding whether to use this

The old README explained the repository to someone who had already decided to read it. A PM landing here gets five seconds and one question: what does this do for me, and what do I type. The rewrite answers that first and moves the reference material behind disclosure blocks. Quick start is now the first section after the hero, with requirements as its opening sentence rather than a section near the bottom, and the Codex /hooks trust step said once instead of three times. It ends with the prompt to paste into the agent, because that is the actual one-click for this audience; a deploy button would land a visitor in a terminal where neither CLI is installed or authenticated, which is where this toolkit does nothing. A new diagram replaces the enforcement flowchart: the loop a turn actually runs, from the request through the injected memory pointer and stage, the skill, the gates, the artefact, and back into memory for the next session. The flowchart it replaces restated the hook table directly above it. The pipeline diagram is unchanged. Four use cases carry their own invocation and name the artefact that comes out, which is what a reader is trying to picture. Six collapsed blocks hold what only a contributor needs: hook wiring per harness, the shapes the eval pipeline actually writes (an evals.json case, a labels.jsonl record, and the overall block of benchmark_all.json as it stands, with its nulls, which is the no-published-results rule rendered as data), memory on disk, the scripts table, the repository tree, and troubleshooting. Every count is stated once, as a digit, because the next commit makes the validator check them against the tree. The two badges that encoded counts are gone, since nothing verified them; the validate workflow badge takes their place, and PRs welcome now points at CONTRIBUTING.md instead of the pull request list. The At a glance table is deleted. Its eight rows each repeated the section they pointed at, and the contents list above them does the same job in fewer lines. If you want it back, the honest place is a caption under the new diagram, not a section of its own. The slogan is factual about the mechanism: the hooks enforce at tool-call time and the model does not get to opt out. A stronger line about gates it cannot talk its way past was rejected, because every gate here has a documented per-content override. No claim was added that the repository does not sustain. The grading section says the manifests hold 85 eval cases and still says no measured result is published; the fixture contract and the proposal loop are described because they exist. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B43: the three rules a contributor cannot guess, and where to send a security report

CONTRIBUTING.md, SECURITY.md and a pull request template. The repo had none of the three, and the README is about to link them. CONTRIBUTING.md carries only what the tree does not tell you. The battery of twenty commands before every commit, including the second validator run under -S, which exists so the frontmatter parser has to reach the same verdict without PyYAML. That skills/ is canonical and the two mirror directories are byte copies sync_skills.py regenerates, so an edit to a mirror is caught by the drift check rather than silently overwritten later. And that an eval case without a matching assertion block and fixture pair is not a case: the contract those fixtures satisfy is in EVAL_PROTOCOL, and the part worth repeating is that a block whose own labels, read back as an answer, would pass is matching vocabulary rather than behaviour. It also warns that the README is checked, because the next commit makes that true: adding a skill or a script turns CI red until the README says so. A README that drifts is worse than no README, since it is read as current. SECURITY.md points at GitHub's private vulnerability reporting, which is a setting you need to enable on the repository; until then it says to ask for a private channel rather than filing details in public. It names what is worth reporting, mostly the path boundaries and the PII refusal in the memory layer, and it says plainly what the gates are not. Each one has a documented per-content override and anyone with write access can bypass them, so the override working as documented is not a vulnerability. Inventing a security contact address would have been worse than none. The pull request template is three prompts, not a checklist: what changed and why, the validation against the exact head, and what would change the approach. Everything it asks for is something a reviewer here has had to ask for by hand. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B42 review: the docs and the suite say what the code does

The last group from the review: seven places where a sentence or a test claimed more than the code delivered. Two are fixed by making the code true, five by correcting the sentence.
