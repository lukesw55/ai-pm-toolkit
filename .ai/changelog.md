## 2026-09-16: B42: the check mode runs the suite and reports it step by step

propose_eval_updates.py gains a check subcommand, the half of the loop the owner asked for: after a human pastes a candidate fixture, the system runs the tests and communicates each step so he can decide and calibrate. Seven steps. The first judges the pasted object before anything runs, because nothing else in the repo validates that file: it checks the six keys in order, that near_miss carries text and fails, that no eval has a second object, and that the pair exists in both the assertion blocks and the manifest. Without it a missing key surfaces as a KeyError traceback from the suite instead of a sentence. Then the suite runs once with --json-summary, and steps three to six report the eight fixtures derived from this pair with their bands, the declared against the actual near-miss failure, the discrimination gap against its floor, and the nine derived attacks against their ceiling. Step seven lists failures elsewhere in the suite, which is the collateral a tightened regex actually causes and the thing a human tightening one will hit. The verdict names what to change rather than restating the failure: a near miss that fails more than the assertion it names is a bad fixture, not a bad assertion, because loosening the block to let it through would also let the bad fixture through. It closes by saying that a green suite means the fixtures it has do not contradict the assertion, not that the assertion is right. While writing step one it found that the fixtures file mixes both key orders inside near_miss, 79 objects one way and 6 the other. Order matters for the object's own keys, so a paste reads like the rest of the file; inside near_miss it is cosmetic, so the check does not demand it. Five test cases: the green path against the real tree read-only, and four red paths against a copy of the two directories the suite reads. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B42: an opt-in JSON summary for the grader suite, and the duplicate pair it never caught

test_grade_evals.py gains --json-summary <path>. The summary is written to a file, never to stdout, and every print is byte-identical with or without the flag, verified by diffing the two runs; run() stays callable with no arguments, so CI and the battery are untouched. It carries the per-fixture bands, the per-pair discrimination gap, the declared and actual near-miss failures, the four punctuation joins and five label soups per pair, and the coverage gaps. The per-assertion detail is emitted only for a fixture that failed, because it exists nowhere else in machine-readable form and emitting it for all 705 would bloat the file for no reader. The alternative was parsing the printed lines from the checking script. That loses on three counts: the per-assertion result exists only inside a failure string joined by "; ", and assertion labels are free prose containing commas and colons; the aggregate lines hide which pair failed; and it would turn twenty print statements into an undeclared API that the next reformat breaks with no test to say so. The same commit closes a hole the suite had all along: the fixtures file holds exactly one object per eval and all 85 exist, but a second object for an eval that already has one passed every check, because the strict-pair set collapses the duplicate and the coverage tests are subset tests. Three lines now fail on it. Verified by appending a duplicate in memory and watching the suite go red; today the check finds nothing. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B42: propose_eval_updates.py turns labelled disagreements into proposals

The grader already reports where it disagrees with the humans; nothing turned that signal into a reviewable change. propose reads the labels for an iteration, re-grades the recorded output with grade_run rather than trusting a grading.json the workspace may have left stale, and writes one markdown proposal plus a JSON sibling under docs/benchmarks/<iteration>/proposals/, with an index naming every label key and its outcome. It proposes and never applies. A grader that rewrote its assertions from the outputs it grades would stop measuring the model and start measuring itself, so no code path writes to an eval manifest, to the ASSERTIONS block or to the fixtures file, and a test asserts all three are byte-identical after a pass. No regex is generated: the proposal names a direction and a rule in plain English composed only from the assertion labels involved and the labeler's reason, and the Python block is commented out end to end. Five categories with a precedence: stale-rubric asks for a relabel without --supersede, a split is reported and never resolved to the worse verdict, an eval-defect handle outranks a false accept and counts how many labels go stale if the rubric changes, and a false accept or false reject carries a fixture candidate. The candidate is a replacement for one slot of the existing pair, never a second object, because the file holds exactly one object per eval and the coverage checks are subset tests that would not notice a duplicate; when the candidate is already another slot's value the proposal says so, since one text cannot be both the answer to accept and the answer to reject. A negative fixture from a run that really failed hardens the grader; a positive one copied from a run it already accepts makes it agree with that model by construction, so a good candidate is marked for a rewrite by hand. Agreement, and any run nobody labelled, propose nothing. The excerpt is bounded by default because the workspace is gitignored and docs/ is tracked: a full output would publish model text into git permanently and grow a corpus of it beside the fixtures file. The markdown carries no timestamp, so a second pass over an unchanged run produces the same bytes and content_sha256 detects a reviewer's annotations, which are refused rather than overwritten unless --force. 19 test cases in the test_label_eval_run.py sandbox shape. Registered in the battery, the CI matrix and the README tables. Full docs/REPO_HEALTH.md battery green before the commit.
