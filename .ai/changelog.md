## 2026-09-16: The B25 handoff: what a measured iteration may not change, and the order of operations

docs/EVAL_PROTOCOL.md stays the one protocol. This adds a section to it rather than a second runbook, because two documents describing the same pilot is how they drift apart. I measured what the protocol already covered before writing anything. A fresh isolated session per output, the pairing rule that forbids attributing a difference to the harness when the models differ, one attempt directory per attempt with the failures kept, provenance with argv and version and seed, the per-harness runbook, the per-harness report, labelling, the smoke run and verified_harness_versions were all already there. Two rules were not written down anywhere and a third already existed and is made explicit and stricter here. The first is that the measurement instrument is frozen for the whole iteration, and the instrument is not only the grader: it is the commit, the manifests and prompts, the expected outputs, the skill bundle and dependency hashes, the assertions, the fixtures, the thresholds, the model, the harness version, the runner arguments and the isolation configuration. Changing any one of them starts a new iteration. This is worth stating now that the proposal loop exists, because applying a proposal mid-iteration swaps the grader underneath outputs already recorded. The second is the one that already existed: Record outputs said to save the assistant output as UTF-8 without editing it, and this states what that covers, namely formatting, whitespace and any change that would make an assertion match, with an unparseable output kept as a failed attempt rather than repaired. The third is that the keep, fix, simplify or remove criteria are pre-registered in a tracked docs/benchmarks/<measured-iteration>/pre-registration.md, committed before any output is inspected for quality, since criteria written afterwards describe the results. The order of operations is fourteen numbered steps that sequence what the sections below already specify, and it keeps the smoke run and the measured run in separate iterations, because adding a verified harness version changes the manifest and rule 1 forbids that inside an iteration that has already recorded outputs. Two of the steps are new requirements: blind the first human read to the configuration where the tooling allows it and disclose the absence of blinding where it does not, and report paired counts, critical failures, negative controls, grader disagreement, token cost and duration. A closing paragraph sets the honest ceiling with the real denominators, which differ per skill: pm-phase-discover carries 6 prompts, pm-transversal-comms 5 and pm-prioritization-regua-comum 4, so one pair is worth 16.7, 20 and 25 points respectively. The report names the pair count and denominator per skill and gives paired cases and counts, and must not present a percentage over four to six cases as an estimate with a confidence interval. No authenticated model run happens in this environment and none is implied here. The deterministic dry-run and the full battery are what ran. Full docs/REPO_HEALTH.md battery green before the commit.
