## 2026-09-16: B42: propose_eval_updates.py turns labelled disagreements into proposals

The grader already reports where it disagrees with the humans; nothing turned that signal into a reviewable change. propose reads the labels for an iteration, re-grades the recorded output with grade_run rather than trusting a grading.json the workspace may have left stale, and writes one markdown proposal plus a JSON sibling under docs/benchmarks/<iteration>/proposals/, with an index naming every label key and its outcome. It proposes and never applies. A grader that rewrote its assertions from the outputs it grades would stop measuring the model and start measuring itself, so no code path writes to an eval manifest, to the ASSERTIONS block or to the fixtures file, and a test asserts all three are byte-identical after a pass. No regex is generated: the proposal names a direction and a rule in plain English composed only from the assertion labels involved and the labeler's reason, and the Python block is commented out end to end. Five categories with a precedence: stale-rubric asks for a relabel without --supersede, a split is reported and never resolved to the worse verdict, an eval-defect handle outranks a false accept and counts how many labels go stale if the rubric changes, and a false accept or false reject carries a fixture candidate. The candidate is a replacement for one slot of the existing pair, never a second object, because the file holds exactly one object per eval and the coverage checks are subset tests that would not notice a duplicate; when the candidate is already another slot's value the proposal says so, since one text cannot be both the answer to accept and the answer to reject. A negative fixture from a run that really failed hardens the grader; a positive one copied from a run it already accepts makes it agree with that model by construction, so a good candidate is marked for a rewrite by hand. Agreement, and any run nobody labelled, propose nothing. The excerpt is bounded by default because the workspace is gitignored and docs/ is tracked: a full output would publish model text into git permanently and grow a corpus of it beside the fixtures file. The markdown carries no timestamp, so a second pass over an unchanged run produces the same bytes and content_sha256 detects a reviewer's annotations, which are refused rather than overwritten unless --force. 19 test cases in the test_label_eval_run.py sandbox shape. Registered in the battery, the CI matrix and the README tables. Full docs/REPO_HEALTH.md battery green before the commit.
