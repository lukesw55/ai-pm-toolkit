## 2026-09-16: B42 review: golden_set reads what a spreadsheet writes, and checks what the flags skipped

The same review went through golden_set.py. Nine findings, all small, one of them the kind that makes a tool useless on first contact. A sheet saved from a spreadsheet as "CSV UTF-8" carries a byte-order mark, so the first column read as something other than id and every subcommand refused the file with a message about the header. The docstring says a PM opens this in a spreadsheet, which makes that the normal path, not an edge case. The sheet is read as utf-8-sig now; the rewrite stays utf-8, so the mark does not come back. Confinement stopped at the directory. context_paths confines <slug>/evals/<feature>, but the file name was joined on afterwards, so a symlink at <feature>/golden-set.csv pointing out of the project was followed by every read and by init's write, which reported an in-project path while writing somewhere else. Same class as the init_context --org finding from the third review round of PR #21, same fix: the leaf goes through project_path too. write_sheet replaced the sheet with a temp file, and os.replace keeps the temp file's mode, so every add silently narrowed 0644 to 0600. The mode is carried over now. Line numbers in the messages were counted rather than read, so one blank line or one quoted field spanning lines shifted every number after it. They come from the reader now and name the row's last physical line. Those messages exist to say where to look. --id skipped every validation the other fields get: it could be empty, span lines, or be non-numeric, and a non-numeric id disables the automatic id for every later add without saying so. It is validated like the rest now, with a warning rather than a refusal for the last case, because the error that suggests --id in the first place allows it. --stale-after was never parsed as a date, only compared as text, so a typo like 2026-1-1 sorted after every ISO date and flagged every row stale, which with --strict is an exit code. It is parsed before the sheet is read, and the comparison is between dates. check accepted an empty input locator and an empty expected behaviour, then reported two empty locators as duplicates of each other. Both are errors now and the duplicate scan skips them. It also warns when a cell starts with =, + or @, which a spreadsheet evaluates as a formula rather than showing; a leading minus is left out on purpose, because in this data it is a negative number or a dash far more often than a formula. Last, next_id guarded with isdigit() where int() is narrower, so an id like a superscript digit reached int() and produced the wrong message. isdecimal() is the guard that matches. Twelve regression cases, 48 in the file. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B42 review: the pass survives the inputs it does not control

Four findings from the same review. Each is an input the pass reads and does not write: a record another script left, a label line a person merged by hand, and the model text the card quotes. A truncated grading.json aborted the whole pass. build_proposal turns every other unusable run into an outcome row and its docstring promises it never raises, but this one read went through an unguarded json.loads, so a pass killed mid-write elsewhere left this one dead: cards already written stayed on disk, the index was never written, and the message named no skill, eval or path. A grading.json holding an array was worse, because stored.get raised an AttributeError that main does not catch, so the user got a traceback. The read is now guarded and typed, an unusable record is a warning naming the run and re-graded from scratch anyway, and the pass continues. That file is only ever consulted to say so when it disagrees with this pass. label_eval_run treats supersedes as optional and inserts no default, so a hand-written or hand-merged labels.jsonl line without it is a valid label that grade_all reads without complaint. The proposal quoted the field with record[k] and the pass died with "propose_eval_updates: 'supersedes'", one quoted word, losing every other label in the iteration. The excerpt went into a three-backtick fence with no guard against the fences in what it wraps, and outputs for these skills carry code blocks, decks and tables. CommonMark closes a fence only with a run at least as long as the opener, so the model's own closing fence closed the card's: everything after it rendered as live markdown, the model's headings became the card's headings, and the two sections that carry the recommendation ended up inside a code block. Arbitrary model text could inject a heading into a tracked page. Both fences that wrap model text are now computed from it. The pasted candidate gets the same treatment, because the candidate is that output. Last, a pipe in a labeler's reason opened a column in the labels table. Every table cell in the card is escaped now. Four regression cases, 34 in the file: three shapes of broken grading record, a label line with the key removed, an output carrying a fenced block where the card's fences must still balance and the model's heading must stay inside one, and a reason with a pipe. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B42 review: the index describes the iteration, and a retracted card says so

Two more findings from the same review, both about a tracked file that stops matching the labels it cites. A pass filtered with --skill or --eval rewrote index.md and index.json from the rows it visited, under a header that reads "Every label in this iteration and what came of it", while leaving every other card on disk. The cards it dropped were then present in tracked docs/ and named nowhere. A pass that matched nothing already left the previous index alone, which is the right behaviour and stays: the guard tested for an empty pass and not for a partial one. Rows the pass did not visit are now carried from the existing index, keyed by skill, eval, config and output hash, and the whole set is sorted before it is written. An index that does not parse is reported and rewritten from scratch rather than aborting the pass. index.json also carried a generated_at, so every pass produced a diff on a tracked file even when no card changed. It is gone, for the reason render_markdown already carries a comment about: the git history is the timestamp. The per-pass state moved out of the row with it, because the index records what the iteration says, not what this invocation did; the printed lines still report each write. The second finding: when a run stopped being a disagreement, because a second labeler created a split or a relabel turned it into agreement, no code path touched the card. The index said split while the .md and .json beside it still said false-accept, status proposed, with a fixture candidate to paste. The card is now marked retracted, with the reason, and its markdown opens with a line saying the recommendation no longer follows from the labels. It is not deleted, because a person may already have acted on it. A card a human decided is never rewritten; a card whose markdown was edited by hand is a warning naming the file; retracting twice does not stack banners; and a card that becomes a disagreement again is proposed again. Five regression cases, 30 in the file: the filtered pass names every card on disk, two passes write the same index bytes, a split retracts the card and the index names it, retraction is idempotent, and a decided card survives. Full docs/REPO_HEALTH.md battery green before the commit.
