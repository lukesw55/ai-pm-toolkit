## 2026-09-16: B43: the README's counts come from the tree, and the validator says so

The README carried four counts and a scripts table that nothing verified. The old one said 21 skills in two places and 79 eval cases in a sentence dated to the day someone last counted; the contents list had fifteen anchors for sixteen headings, and no one had noticed. Numbers in a README rot silently, which is worse than having none, because a reader treats them as current. check_readme_contract recomputes them from the filesystem: skills from skills/*/SKILL.md, blocking hooks from hooks/*-gate.sh, agents from .github/agents/*.agent.md, and the eval total and its four category counts from the manifests. Each pattern has to match exactly once. Zero matches is an error rather than a pass, because a reworded sentence would otherwise switch the check off without anyone knowing, and more than one means the number lives in two places and the copies will drift. The rule that follows is written in CONTRIBUTING.md: a validated count is a digit, said once. Two structural checks come with it. Every file in scripts/ needs a row in the table and no row may name a file that is gone, which is how those two rows for the scripts added last week would have been caught. And the contents list has to match the top-level headings in order, which is the fifteen-for-sixteen case. The messages name both sides, in the style of the rest of the validator: says skills 20, the tree has 21. The consequence is deliberate and CONTRIBUTING.md states it: adding a twenty-second skill turns CI red until the README is updated. That is the point of the check, and a contributor deserves to know before they hit it. Six cases in test_validate_repo.py, each against a small temporary tree: a README that matches, a count that drifted, a count stated twice, a missing row, a row for a script that is gone, and a contents list out of step. 67 cases in the file. Full docs/REPO_HEALTH.md battery green before the commit.

## 2026-09-16: B43: the README rewritten for the person deciding whether to use this

## 2026-09-16: B43: the three rules a contributor cannot guess, and where to send a security report

CONTRIBUTING.md, SECURITY.md and a pull request template. The repo had none of the three, and the README is about to link them. CONTRIBUTING.md carries only what the tree does not tell you. The battery of twenty commands before every commit, including the second validator run under -S, which exists so the frontmatter parser has to reach the same verdict without PyYAML. That skills/ is canonical and the two mirror directories are byte copies sync_skills.py regenerates, so an edit to a mirror is caught by the drift check rather than silently overwritten later. And that an eval case without a matching assertion block and fixture pair is not a case: the contract those fixtures satisfy is in EVAL_PROTOCOL, and the part worth repeating is that a block whose own labels, read back as an answer, would pass is matching vocabulary rather than behaviour. It also warns that the README is checked, because the next commit makes that true: adding a skill or a script turns CI red until the README says so. A README that drifts is worse than no README, since it is read as current. SECURITY.md points at GitHub's private vulnerability reporting, which is a setting you need to enable on the repository; until then it says to ask for a private channel rather than filing details in public. It names what is worth reporting, mostly the path boundaries and the PII refusal in the memory layer, and it says plainly what the gates are not. Each one has a documented per-content override and anyone with write access can bypass them, so the override working as documented is not a vulnerability. Inventing a security contact address would have been worse than none. The pull request template is three prompts, not a checklist: what changed and why, the validation against the exact head, and what would change the approach. Everything it asks for is something a reviewer here has had to ask for by hand. Full docs/REPO_HEALTH.md battery green before the commit.
