## 2026-09-16: B42: golden_set.py, the product side of the loop

The reference in skills/pm-archetype-ai has said since B33 that every production failure becomes a new golden row before the fix ships, and published the two paths a golden set lives at. Nothing wrote them: the path was documentation only, with no script, no template and no check. This adds golden_set.py with init, add, show, list and check, writing exactly the two files that reference already publishes and nothing else. Every field of a row comes from a flag a person typed. The script never reads a model's output, because a golden row whose expected behaviour was copied from what the model produced makes the set agree with the model, which is the same failure the toolkit's own grader guards against one layer up. Confinement is context_paths' job, not a new implementation: a PII slug, a PII segment as the feature name, traversal on either side and a projects root behind a symlink are all refused there, and the tests prove each one. add reads and validates the whole sheet before appending, so a renamed column, a short row or a duplicate id stops the append with the file byte-identical, which is what makes it safe to run against a sheet a PM has been editing in a spreadsheet. Writes are atomic through a temp file in the same directory. The header is the reference's words, spaces included, because a PM opens this in a spreadsheet. check covers the rules that can be checked mechanically, including the one that matters most: a set whose only failure is synthetic does not satisfy the rule that at least one row is a failure the team has really seen. A set with no failure in it is a scrapbook, not a test. Two tracked templates under .ai/memory/_templates/evals/. The CSV template is the header line alone: a seeded example row would be a fabricated failure in every new set. Neither is wired into init_context.PROJECT_FILES, which creates flat files in the project root and from which the context tests derive the expected file set; most projects never run an eval, so the tree is created on demand instead of bootstrapped into all of them. 36 test cases in the test_memory.py sandbox shape. Full docs/REPO_HEALTH.md battery green before the commit.
